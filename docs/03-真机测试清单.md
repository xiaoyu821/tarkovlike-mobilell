# 03 · Unity 真机测试清单（Android）

> 适用：M0 及之后所有需要上真机的阶段。
> 结论：**EditMode 单测只能在编辑器跑；真机验证靠 PlayMode 测试 + 实机试玩。**
> 数据层能否在手机上跑通，取决于下面第 4 节的 StreamingAssets 处理，必须先看。
> 本机不装 Unity 时，可改用 [04-云端构建](04-云端构建.md) 产出 APK。

---

## 0. 前置条件

| 项 | 要求 |
|---|---|
| Unity | 6000.0.32f1（与 `ProjectSettings/ProjectVersion.txt` 一致；换版本则改这里） |
| 模块 | Android Build Support（含 SDK / NDK / OpenJDK） |
| 手机 | 中端（骁龙 7 系）+ 低端各一台，Android 8.0+ |
| 连接 | USB 调试开启，`adb devices` 能看到设备 |
| 包名 | `com.yourstudio.tarkovlike`（Player Settings 自行改） |

---

## 1. 首次打开工程

1. Unity Hub → Add → 选择仓库根目录 `/workspace`。
2. 等待 Package Manager 解析 `Packages/manifest.json`。
   - 若报「版本不存在」，按当前 Unity 版本改 manifest 里的包版本，不要删包。
3. Console 必须 **0 error**。允许 warning（如 Odin 未安装）。
4. 检查 `Project Settings > Player > Active Input Handling`：
   - 选 `Input System Package (New)` 或 `Both`，否则触屏完全没反应。
5. M0 建好 URP Asset 后，`Project Settings > Graphics` 与 `Quality` 都要指向它，否则真机黑屏。

---

## 2. 编辑器内跑 EditMode 单测

`Window > General > Test Runner > EditMode > Run All`

预期 **9 个用例全绿**：

| 测试类 | 用例数 | 覆盖 |
|---|---|---|
| `DataCatalogTests` | 5 | 数据加载、R1~R9、断链、口径、堆叠 |
| `LootRollerTests` | 4 | 确定性、数量区间、零权重、权重分布 |

命令行（CI 用）：

```bash
Unity -batchmode -nographics -projectPath /workspace \
  -runTests -testPlatform EditMode \
  -testResults /tmp/editmode-results.xml -logFile /tmp/editmode.log -quit
```

> EditMode 测试**不会**在手机上运行，它验证的是编辑器内的数据与逻辑。

## 3. 构建 APK

`File > Build Settings`：

1. Platform 切到 **Android** → `Switch Platform`。
2. `Player Settings`：

| 设置 | 值 |
|---|---|
| Scripting Backend | IL2CPP |
| Target Architectures | ARM64（低端机需要时加 ARMv7） |
| Minimum API Level | Android 8.0 (API 24) |
| Target API Level | 跟随 Google Play 当年要求（2026 按 API 35+） |
| Graphics APIs | Vulkan + OpenGLES3 |
| Color Space | Linear |
| Multithreaded Rendering | 开 |
| Internet Access | Require（M3 联网前可 Auto） |

3. `Build Settings > Texture Compression` 选 **ASTC**。
4. M0 阶段勾选 `Development Build` + `Script Debugging`，方便看日志。
5. `Build And Run`。

> 首次构建 IL2CPP 较慢，属正常。CI 自动打包需要额外写 `BuildScript`，M1 再补。

## 4. ⚠️ 阻断项：StreamingAssets 在 Android 读不到

**现状**：`JsonCatalogLoader.LoadFromDirectory()` 用的是 `System.IO.File.ReadAllText`。

在 Android 上 `Application.streamingAssetsPath` 指向 APK 内部：

```
jar:file:///data/app/.../base.apk!/assets
```

`System.IO.File` **无法读取该路径**。编辑器 / PC 正常，真机必失败。

### 处理方式（M0 必须选一个）

**方案 A（推荐）：首次启动把数据复制到 persistentDataPath**

```csharp
using System.Collections;
using System.IO;
using Game.Data;
using UnityEngine;
using UnityEngine.Networking;

public sealed class GameDataBootstrap : MonoBehaviour
{
    static readonly string[] Files =
    {
        "items.json", "weapons.json", "ammo.json", "armor.json", "loot_tables.json"
    };

    public DataCatalog Catalog { get; private set; }

    IEnumerator Start()
    {
        var srcDir = Path.Combine(Application.streamingAssetsPath, "GameData");
        var dstDir = Path.Combine(Application.persistentDataPath, "GameData");
        Directory.CreateDirectory(dstDir);

        foreach (var name in Files)
        {
            var src = Path.Combine(srcDir, name);
            var dst = Path.Combine(dstDir, name);

            if (src.Contains("://"))
            {
                using var req = UnityWebRequest.Get(src);
                yield return req.SendWebRequest();
                if (req.result != UnityWebRequest.Result.Success)
                {
                    Debug.LogError($"读取 {name} 失败: {req.error}");
                    yield break;
                }
                File.WriteAllBytes(dst, req.downloadHandler.data);
            }
            else
            {
                File.Copy(src, dst, true);
            }
        }

        Catalog = JsonCatalogLoader.LoadFromDirectory(dstDir);
        Catalog.ThrowIfInvalid();
        Debug.Log($"[Data] items={Catalog.Items.Count} weapons={Catalog.Weapons.Count} " +
                  $"ammo={Catalog.Ammo.Count} armor={Catalog.Armor.Count} loot={Catalog.LootTables.Count}");
    }
}
```

验收：logcat 里出现 `items=18 weapons=5 ammo=5 armor=3 loot=3`。这是**数据层在手机上真正跑通**的证据。

**方案 B**：改造 loader 注入 `Func<string, string>` 读取器，Android 用协程 + UnityWebRequest（异步，改动大）。
**方案 C**：M2 改 Addressables 加载 TextAsset（最干净，但 M0 不做）。

> 方案 A 保持 `Game.Data` 无引擎依赖，只是把「可读目录」换成了 persistentDataPath。

## 5. 真机启动检查

| # | 检查项 | 预期 |
|---|---|---|
| 1 | 安装启动 | 无崩溃，进场景 |
| 2 | 横屏 | 锁定横屏，两侧刘海不挡 HUD |
| 3 | 数据加载 | logcat 打印 `items=18 ...`，无 Validation 异常 |
| 4 | 切后台再回来 | 不重启、不丢状态（M1 起） |
| 5 | 首次冷启动 | 中端机 < 10s |

## 6. M0 手感验收（必须真机，人肉）

**操作**

- [ ] 左摇杆移动跟手，无死区漂移
- [ ] 右半屏拖拽瞄准，灵敏度可调（建议 0.2~0.5°/像素）
- [ ] 开火 / 开镜 / 蹲 / 换弹 / 切枪 5 个按钮，触摸区 ≥ 60px
- [ ] 侧身按钮（可关）不误触
- [ ] 辅助瞄准：吸附 3~6°，减速 30%~60%，可关

**枪感**

- [ ] 连发 10 发后准星能回正，不飘到天上
- [ ] 换弹动作与音效对齐，无「已开枪但弹匣没扣」
- [ ] 命中三件套齐全：准星跳动 + 命中音 + 血花
- [ ] TTK 落在 0.4~1.2s（对 100 HP 目标）

**AI**

- [ ] 胶囊 AI 会追、不穿墙、不抽搐
- [ ] 玩家绕掩体后 AI 会丢失目标再搜索

**总验收**

- [ ] 自己连续打 10 分钟不觉得难受（M0 生死线）

## 8. 真机跑 PlayMode 测试（可选，M1 起）

1. 新增 `Assets/Tests/PlayMode` 与对应 asmdef（引用 `Game.Data`、`UnityEngine.TestRunner`、`nunit.framework`）。
2. 在 Test Runner 切到 `PlayMode` → `Run All in Player (Android)`。
3. 用例建议：`GameDataBootstrap` 完成后断言 `Catalog.Items.Count == 18` 且 `Validate()` 为空。

> 这是手机上验证 C# 数据层的最直接方式，比看日志更严格。

## 10. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 触屏完全没反应 | Active Input Handling 未切 | 改 Player Settings 后重启编辑器 |
| 真机黑屏 | URP Asset 未挂到 Graphics/Quality | 指定 URP Asset |
| 数据加载 FileNotFound | StreamingAssets 在 APK 内 | 用第 4 节方案 A |
| 包解析报版本不存在 | manifest 包版本与编辑器不匹配 | 改版本号，不删包 |
| IL2CPP 构建失败 | NDK/JDK 未装或版本不符 | Unity Hub 补装 Android 模块 |
| 刘海挡 HUD | 未做 Safe Area | 用 `Screen.safeArea` 布局 |
| 构建后没日志 | 非 Development Build | 勾选 Development Build |
