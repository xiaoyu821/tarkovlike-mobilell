# 02 · 数据结构

> 唯一事实来源。代码、数据表、校验工具都以本文档（及 `schemas/`）为准。
> 改 schema 必须同时改：本文档 → `schemas/*.schema.json` → C# 模型 → 示例数据 → 单测。

---

## 1. 设计原则（相对原计划的改进点）

| # | 决策 | 原因 |
|---|---|---|
| 1 | 所有 ID 为**稳定字符串 + 前缀**，一旦发布永不复用 | 存档、掉落记录、埋点都引用 ID；改 ID = 坏档 |
| 2 | 显示名与本地化 key 分离（`displayName` 仅作开发期回退） | 后期加多语言不用改数据 |
| 3 | 数值统一用**整数 + 明确单位**（克 / 卢布 / RPM / m/s / mm） | 避免浮点漂移，方便对账与平衡 |
| 4 | 每份数据文件带 `schemaVersion` | 热更与存档迁移的前提 |
| 5 | 加载器启用 `MissingMemberHandling.Error` | 字段拼错立刻报错，而不是静默丢数据 |
| 6 | 交叉引用由校验器统一检查（编辑器 + CI 同一套规则） | 数据量到 200 件后，靠人眼看不出断链 |
| 7 | 掉落必须支持**种子**随机 | 复现 Bug、做单测、回放同一次掉落 |
| 8 | 弹药也拥有 `ItemData` 记录 | 背包、掉落、拾取逻辑统一，不用写特例 |
| 9 | 武器/品牌名全部虚构 | 规避商标风险（见原计划「法律提醒」） |

## 2. 通用约定

### 2.1 文件与信封

```
Assets/StreamingAssets/GameData/
├── items.json          # 所有可进背包的物品
├── weapons.json        # 武器战斗参数
├── ammo.json           # 弹药参数
├── armor.json          # 护甲/头盔参数
└── loot_tables.json    # 容器掉落表
```

每份文件统一信封：

```json
{
  "schemaVersion": 1,
  "entries": []
}
```

### 2.2 ID 命名

| 类型 | 前缀 | 示例 |
|---|---|---|
| 物品 | `item_` | `item_wpn_kestrel74` |
| 武器 | `wpn_` | `wpn_kestrel74` |
| 弹药 | `ammo_` | `ammo_545_ps` |
| 护甲 | `armor_` | `armor_paca` |
| 掉落表 | `loot_` | `loot_jacket` |

- 只允许 `[a-z0-9_]`，长度 3~64，小写。
- 同一 ID 在**全部文件**中唯一（物品与武器也不能重名）。

### 2.3 单位

| 字段 | 单位 | 类型 |
|---|---|---|
| `weightG` | 克 | int |
| `value` | 卢布 | int |
| `damage` | 点 | int |
| `penetration` | 毫米等效穿深 | int |
| `muzzleVelocity` | 米/秒 | int |
| `rpm` | 发/分钟 | int |
| `durability` | 点 | int |
| `grid.w/h` | 背包格 | int |

### 2.4 本地化

`nameKey` 形如 `l10n.item.bandage`（正则 `^l10n\.[a-z0-9_.]+$`）。
`displayName` 是给开发者看的临时文本，UI 必须优先读 `nameKey`。

## 3. 数据表定义

### 3.1 ItemData（items.json）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | `item_` 前缀 |
| `nameKey` | ✅ | 本地化 key |
| `displayName` | ✅ | 开发期显示名（中文） |
| `category` | ✅ | `weapon` / `ammo` / `armor` / `helmet` / `med` / `loot` / `key` / `container` / `mod` |
| `grid` | ✅ | `{ "w": 1..6, "h": 1..6 }` 背包占格 |
| `weightG` | ✅ | 重量（克） |
| `value` | ✅ | 基础价值（卢布） |
| `stackMax` | ✅ | 堆叠上限，1 表示不可堆叠 |
| `icon` | ✅ | `icons/xxx/yyy.png` |
| `tags` | ✅ | 小写标签数组，可空数组，如 `["med","bleed_stop"]` |

### 3.2 WeaponData（weapons.json）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | `wpn_` 前缀 |
| `itemId` | ✅ | 指向 `category=weapon` 的物品 |
| `caliber` | ✅ | 与所配弹药一致，如 `5.45x39` |
| `baseDamage` | ✅ | 默认弹药下单发伤害，**仅用于 UI 预估与数值审查** |
| `damageMultiplier` | ✅ | 实际结算倍率，`0.5~1.5` |
| `rpm` | ✅ | 射速，`30~1200` |
| `magazineCapacity` | ✅ | 弹匣容量 |
| `recoilCurve` | ✅ | `{ vertical: number[], horizontal: number[] }`，第 n 发取第 n 个（越界取最后一个） |
| `attachmentSlots` | ✅ | 取值 `optic/muzzle/grip/magazine/stock/laser` |
| `allowedAmmo` | ✅ | 允许的弹药 ID 数组（非空） |

**伤害公式（M2 实现）**

```
单发伤害 = ammo.damage × weapon.damageMultiplier
总伤害   = 单发伤害 × ammo.pellets
```

### 3.3 AmmoData（ammo.json）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | `ammo_` 前缀 |
| `itemId` | ✅ | 指向 `category=ammo` 的物品，且 `stackMax > 1` |
| `caliber` | ✅ | `5.45x39` / `9x19` / `12ga` 等 |
| `damage` | ✅ | 单发基础伤害 |
| `penetration` | ✅ | 穿深（mm） |
| `muzzleVelocity` | ✅ | 初速 m/s |
| `pellets` | ✅ | 弹丸数，普通弹为 1，霰弹 > 1 |

### 3.4 ArmorData（armor.json）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | `armor_` 前缀 |
| `itemId` | ✅ | 指向 `category=armor` 或 `helmet` 的物品 |
| `protectionLevel` | ✅ | 1~6，国际护甲等级 |
| `durability` | ✅ | 耐久 |
| `coverage` | ✅ | `head` / `chest` / `limbs` 的子集，非空 |

> 4 部位模型：头、胸、四肢（四肢合并为 `limbs`）。护甲只覆盖 `chest`/`head` 时，命中四肢不吃护甲减伤。

### 3.5 LootTableData（loot_tables.json）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | `loot_` 前缀 |
| `containerType` | ✅ | `jacket` / `weapon_crate` / `scav_body` / … |
| `rolls` | ✅ | `{ min: 1..8, max: >=min }`，抽取次数 |
| `entries` | ✅ | 条目数组（≥1） |
| `entries[].itemId` | ✅ | 指向存在的物品 |
| `entries[].weight` | ✅ | 正整数权重 |
| `entries[].qty` | ✅ | `{ min: 1.., max: >=min }`，且 `max <= 物品.stackMax` |

**掉落语义**

1. 先随机 `rolls` 次数 `n ∈ [min,max]`；
2. 重复 `n` 次：按权重选 1 个条目 → 随机数量 → 加入结果（**同一条目可命中多次**）；
3. 同一容器若需「不重复掉落」，用多个独立掉落表表达，而不是给条目加标记。

## 4. 交叉引用规则（校验器强制）

| 规则 | 说明 |
|---|---|
| R1 | 全局 ID 唯一 |
| R2 | `weapon.itemId` 存在且 `category == weapon` |
| R3 | `weapon.allowedAmmo[*]` 存在，且 `ammo.caliber == weapon.caliber` |
| R4 | `ammo.itemId` 存在且 `category == ammo`、`stackMax > 1` |
| R5 | `armor.itemId` 存在且 `category ∈ {armor, helmet}` |
| R6 | `loot.entries[*].itemId` 存在 |
| R7 | `loot.entries[*].qty.max <= item.stackMax` |
| R8 | `weapon.rpm / magazineCapacity / damageMultiplier` 在允许区间 |
| R9 | `nameKey` 全局唯一 |

校验器：`tools/validate_data.py`（CI 可直接跑，不需要 Unity）。

```bash
python3 tools/validate_data.py            # 校验仓库内数据
python3 tools/validate_data.py --stats    # 附加统计
python3 tools/test_validate_data.py       # 校验器自身单测
```

## 5. C# 层划分

```
Assets/Scripts/Data/            # asmdef: Game.Data（noEngineReferences = true）
├── Models/                     # 纯 POCO，不引用 UnityEngine
│   ├── ItemData.cs
│   ├── WeaponData.cs
│   ├── AmmoData.cs
│   ├── ArmorData.cs
│   └── LootTableData.cs
├── DataCatalog.cs              # 索引 + 交叉引用校验
├── JsonCatalogLoader.cs        # 读取 StreamingAssets JSON（Newtonsoft）
└── LootRoller.cs               # 确定性掉落（System.Random）
```

- `Game.Data` 关闭引擎引用，任何渲染/UI 依赖都无法混进来（编译期强制）。
- 数据与逻辑分离：`LootRoller` 不依赖文件系统，测试直接构造表。
- 编辑器面板（Odin）属于 M1，不在本层。
- **Android 限制**：StreamingAssets 位于 APK 内，`System.IO` 读不到；启动时先复制到 `persistentDataPath` 再把该目录传给 loader。详见 [03-真机测试清单](03-真机测试清单.md) §4。

## 6. 版本与迁移

- `schemaVersion` 当前为 `1`；破坏性改字段时 +1，并在 `docs/` 记录迁移说明。
- 存档中保存 `schemaVersion` 与所有物品 ID；ID 永不复用。
- 发布后新增字段必须可选并带默认值；删除字段走「先弃用一版，再删」。

## 7. 示例数据的规模

当前示例（A1）覆盖：5 把武器、5 种弹药、3 件护甲、18 件物品、3 张掉落表。
目标（M2）：约 200 件物品，由 AI 按本 schema 批量生成，人只调权重与价值。
