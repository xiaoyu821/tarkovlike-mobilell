# 01 · 核心循环

> 本文档定义「一局」的边界与状态流转，是所有系统模块的验收依据。
> 修改本文档必须同步更新 `docs/02-数据结构.md` 与 `Assets/Scripts` 中的对应实现。

---

## 1. 一句话定义

**带装备进图 → 搜刮 → 战斗 → 决定是否撤离 → 带出物资或全部损失。**

一局必须能在 8~10 分钟内完成，并且玩家在死亡时感到「心疼」、撤离时感到「赚到了」。

---

## 2. 局外循环（Hub）

```
仓库 / 配装  →  选择地图与进场点  →  加载 Raid  →  [见 §3]  →  结算  →  仓库
     ↑                                                            │
     └──────────────────── 金币 / 物资 / 任务进度 ─────────────────┘
```

| 节点 | 玩家操作 | 系统职责 |
|---|---|---|
| 仓库 | 整理、出售、修装备 | 持久化、容量限制、堆叠合并 |
| 配装 | 选武器 / 护甲 / 弹药 / 药品 | 合法性校验（口径匹配、槽位、负重） |
| 进图 | 选地图（首发仅 1 张） | 部署点、`RaidManager` 初始化 |
| 结算 | 查看带出与损失 | 写回存档、统计埋点 |

**关键规则**

- 进场前配装**不消耗**金币；死亡时身上与背包内全部物品丢失（保险系统 M3 再做）。
- 仓库容量有限，逼迫玩家做取舍；出售是金币的主要来源。
- 单局时长 8~10 分钟（含部署与撤离），超时未撤离判定为死亡（或按地图规则）。

## 3. 局内状态机（Raid）

```
Loading
  └─> Deploying（无敌 3s，禁止开火）
        └─> InRaid ──┬─> Extracting（站在撤离区累计 10s，可被打断）
                     ├─> Dead（HP 归零 / 超时）
                     └─> Disconnected（宽限 60s 可重连）
                            │
                     ┌──────┴──────┐
                     v             v
                Extracted       Lost（结算）
```

| 状态 | 进入条件 | 退出条件 | 备注 |
|---|---|---|---|
| `Deploying` | 场景加载完成 | 3s 后 | 防出生点被秒 |
| `InRaid` | 部署结束 | 撤离 / 死亡 / 超时 | 主循环 |
| `Extracting` | 进入撤离区且无敌人 | 累计 10s | 受击立即中断并回 `InRaid` |
| `Dead` | 任一部位 HP ≤ 0 且未及时止血（或头部/胸部归零） | 立即 | 尸体转为可搜刮容器 |
| `Extracted` | 撤离完成 | 立即 | 背包内物品写入仓库 |
| `Disconnected` | 网络/进程中断 | 60s 内重连回 `InRaid` | 首发单机仅用于「退出恢复」 |

### 状态机约束（实现时必须遵守）

1. **所有状态切换只允许经由 `RaidManager`**，禁止各系统自行改状态。
2. `Extracting` 期间玩家仍可移动、可被打断；不允许「进圈即安全」。
3. `Dead` 之后禁止再产生伤害事件（防止结算重复）。
4. 结算只能执行一次（幂等），由局 ID + 时间戳去重。

## 4. 一局的目标节奏（8 分钟基准）

| 时间 | 玩家体验 | 设计手段 |
|---|---|---|
| 0:00~1:00 | 紧张、观察 | 出生点远离热点，环境音提示 |
| 1:00~3:00 | 首个决策 | 高价值容器 vs 低风险路线 |
| 3:00~5:00 | 首次交火 | 2~3 个 Scav 巡逻组，枪声吸引 |
| 5:00~7:00 | 背包抉择 | 容量不足，必须丢弃/替换 |
| 7:00~9:00 | 撤离博弈 | 撤离点暴露、可能被蹲 |
| 9:00~10:00 | 结算 | 带出清单 + 损失清单 |

**密度基线（M1/M2 验收用）**

- 地图 300m×300m：Scav 6~8 个，分 3~4 个巡逻组。
- 高价值容器 2~3 个，普通容器 15~25 个。
- 撤离点 4 个，其中 1 个需要钥匙或条件（M2 起）。

---

## 5. 经济与风险（让「死了心疼」成立）

| 项 | 基线 | 说明 |
|---|---|---|
| 初始资金 | 50,000 | 够买 2~3 套基础装备 |
| 基础套装成本 | 15,000~25,000 | 手枪/霰弹 + 轻甲 |
| 单局期望收益 | 20,000~60,000 | 取决于搜刮深度 |
| 目标撤离率 | 45%~60% | 太低挫败，太高无紧张感 |
| 装备损失痛感 | 中 | 一局全损 ≈ 2~3 局收益 |

> 数值全部放在数据表里，**不要硬编码**。调参只改 JSON。

## 6. 反模式（明确不做，防止范围爆炸）

- ❌ 12 部位伤害、20+ 弹药穿透曲线 → 4 部位 + 每口径 2~3 种
- ❌ 拖拽旋转式 Tetris 背包 → 尺寸网格 + 自动整理
- ❌ 自由改枪到零件级 → 6 槽位
- ❌ 藏身处建造、跳蚤市场（首发）
- ❌ 12 人 PvP 同步 → 单机 PvE 首发

---

## 7. 验收标准

| 阶段 | 标准（人肉试玩） |
|---|---|
| M0 | 真机连续打 10 分钟不觉得操作别扭 |
| M1 | 能连续玩 5 局，且想开第 6 局 |
| M2 | 一局 8 分钟有紧张感；死亡会心疼 |
| M3 | 每局开始前有明确的「下一局目标」 |

**判定方式**：找 3 个没看过设计文档的人试玩，只观察、不指导。记录：死亡原因、是否迷路、是否知道该往哪撤离、是否理解背包容量。
